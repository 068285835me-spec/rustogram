# Как добавить свой TURN сервер в сеть MirBeer

Этот мануал для тех кто хочет помочь проекту и поднять свой TURN сервер. Чем больше серверов в разных регионах — тем лучше качество звонков для пользователей.

---

## Зачем это нужно

Кастомный клиент Telegram получает список TURN серверов от централизованного API. При звонке ICE алгоритм выбирает ближайший доступный сервер. Если у тебя есть VPS в регионе где нет наших серверов — твой сервер поможет пользователям из этого региона.

---

## Шаг 1 — Поднять TURN сервер

Следуй мануалу **coturn-deploy-manual.md** — там описан полный процесс развёртывания котурна через Docker.

Коротко:
- VPS с публичным IP
- Домен с A-записью
- Docker + coturn
- TLS сертификат от Let's Encrypt
- Открытые порты: `3478/tcp`, `3478/udp`, `5349/tcp`, `5349/udp`, `49152-65535/udp`

Сохрани значения которые понадобятся для регистрации:
- Домен сервера (например `turn.example.com`)
- Публичный IP
- HMAC секрет (из `openssl rand -hex 32`)
- Регион (страна/город)

---

## Шаг 2 — Проверить что сервер работает

Перед регистрацией убедись что сервер доступен снаружи.

```bash
# Установи утилиты если нет
apt install -y coturn

# Генерируем тестовые credentials
SECRET="твой_hmac_секрет"
TIME=$(date -d "+1 hour" +%s)
USER="$TIME:testuser"
PASS=$(echo -n "$USER" | openssl dgst -binary -sha1 -hmac "$SECRET" | base64)

# Тест STUN
turnutils_stunclient turn.твой-домен.com

# Тест TURN/TLS — должно показать 0% потерь
turnutils_uclient -T -u "$USER" -w "$PASS" turn.твой-домен.com
```

Если видишь `Total lost packets 0 (0.000000%)` — сервер готов к регистрации.

Также можно проверить через браузер на сайте:
```
https://webrtc.github.io/samples/src/content/peerconnection/trickle-ice/
```

Добавь свой сервер и нажми **Gather candidates** — должен появиться кандидат типа `relay`.

---

## Шаг 3 — Зарегистрировать сервер

Свяжись с администратором проекта и передай следующие данные:

```
Domain:      turn.твой-домен.com
IP:          1.2.3.4
UDP Port:    3478
TLS Port:    5349
HMAC Secret: твой_секрет_из_openssl_rand
Region:      netherlands / finland / germany / etc
Owner:       твой_ник
```

> **Важно:** HMAC секрет передавай только по защищённому каналу (например через Telegram с включённым секретным чатом).

После проверки администратор добавит сервер через админ-панель. API автоматически проверит доступность сервера перед добавлением — если сервер недоступен, регистрация не пройдёт.

---

## Как работает проверка при регистрации

При добавлении через админ-панель система автоматически:

1. Отправляет STUN Binding Request на указанный IP и порт
2. Ждёт ответа не более 3 секунд
3. Если сервер не отвечает — регистрация отклоняется с ошибкой

После регистрации сервер проверяется каждую минуту. Если сервер перестаёт отвечать — он автоматически помечается как `unhealthy` и исключается из выдачи клиентам. Как только сервер снова станет доступен — он вернётся в ротацию.

---

## Требования к серверу

| Параметр | Требование |
|---|---|
| Аптайм | Желательно 99%+ |
| Пропускная способность | Минимум 10 Mbit/s |
| Регион | Любой, приоритет — СНГ, Европа |
| TLS | Обязательно (Let's Encrypt) |
| HMAC авторизация | Обязательно |

---

## Что происходит с трафиком

TURN сервер является **слепым релеем** — он не видит содержимое медиапотока. Telegram шифрует медиа end-to-end через SRTP/DTLS. Ключи шифрования согласуются напрямую между клиентами и никогда не проходят через TURN сервер.

Сервер видит только:
- IP адреса клиентов
- Объём трафика
- Временные метки пакетов

Содержимое разговора — никогда.

---

## Обновление сертификата

Let's Encrypt сертификаты действуют 90 дней. Certbot обновляет их автоматически. Убедись что хук для перезапуска котурна настроен:

```bash
# Проверяем хук
cat /etc/letsencrypt/renewal-hooks/deploy/coturn.sh

# Тест автообновления
certbot renew --dry-run
```

## Если что-то пошло не так

**Сервер зарегистрирован но помечен как unhealthy:**
```bash
# Проверь открытые порты
iptables -L INPUT -n | grep -E '3478|5349'

# Проверь что котурн запущен
docker ps | grep coturn
docker compose -f /opt/coturn/docker-compose.yml logs | tail -20
```

**Сервер не проходит проверку при регистрации:**
```bash
# Проверь доступность с внешней машины
turnutils_stunclient твой-домен.com

# Проверь firewall — UDP 3478 должен быть открыт
nc -u твой-IP 3478
```

**Сертификат просрочен:**
```bash
certbot renew --force-renewal
# Хук автоматически скопирует новый сертификат и перезапустит котурн
```
